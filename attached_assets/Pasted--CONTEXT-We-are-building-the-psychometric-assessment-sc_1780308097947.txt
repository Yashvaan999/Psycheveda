# CONTEXT
We are building the psychometric assessment scoring engine for "Psycheveda". The app uses a 30-question diagnostic questionnaire to evaluate a user's "Success Identity". It tracks 5 key sub-parameters (Bio-Energy, Cognitive Performance, Goal Readiness, Physical Asset, and Stress Resistance) which roll up into 4 master identity tiers: Survivor (0-25%), Soldier (25-50%), Warrior (50-75%), and Superhero (75-100%).

# OBJECTIVE
Write a robust, production-ready JavaScript/TypeScript module (compatible with a Node.js/Express backend on Replit) that ingests an array of 30 user question responses, maps and calculates the precise score vectors, and renders a concise summary payload alongside an ASCII or Canvas-based unified parameters chart.

# CORE ALGORITHM MATHEMATICS
1. Answer Weighting Configuration:
   - For POSITIVE ENABLERS (Questions: 1, 2, 3, 7, 12, 14, 15, 17, 18, 25, 27):
     * Strongly Agree = +2, Agree = +1, Neutral = 0, Disagree = -1, Strongly Disagree = -2
   - For BIOCHEMICAL/PSYCHOLOGICAL DRAINERS (Questions: 4, 5, 6, 8, 9, 10, 11, 13, 16, 19, 20, 21, 22, 23, 24, 26, 28, 29, 30):
     * Strongly Agree = -2, Agree = -1, Neutral = 0, Disagree = +1, Strongly Disagree = +2

2. Parameter Mapping Sub-Vectors (Max 12 points per sub-vector to convert into local %):
   - Vector A [Bio-Energy Balance]: Q9, Q10, Q11, Q13, Q16, Q20
   - Vector B [Cognitive Performance]: Q2, Q3, Q12, Q14, Q19, Q28
   - Vector C [Goal-Pursuit Readiness]: Q1, Q7, Q27 + (Aggregated Enabler Averages)
   - Vector D [Physical Base Asset]: Q8, Q17, Q23, Q24, Q25, Q26
   - Vector E [Stress & Anxiety Resistance]: Q4, Q5, Q6, Q15, Q21, Q22, Q29, Q30

3. Tier Allocations (Based on Overall Aggregated Percentage):
   - 0% - 25%: SURVIVOR (Unconscious Creation, Biologically Bankrupt)
   - 25% - 50%: SOLDIER (Unconscious Creation, Willpower-Depleted Functional State)
   - 50% - 75%: WARRIOR (Conscious Creation, Active Ambition vs Variable Biochemistry Balance)
   - 75% - 100%: SUPERHERO (Conscious Creation, Optimal Unstoppable Integration)

# PROGRAMMING REQUIREMENTS
- Create a clean script export function `calculateSuccessIdentity(userResponses)`.
- Input: An array of objects matching `[{ questionId: 1, value: "Strongly Agree" }, ... ]`.
- Output: Return a clean JSON data structure containing:
  1. `overallPercentage` (Integer)
  2. `assignedTier` (String)
  3. `subParameters` (Object containing individual % scores for vectors A, B, C, D, E)
  4. `asciiGraph` (A beautiful, pre-formatted multi-line layout string that presents all 5 vector metrics cleanly inside a unified horizontal comparative bar layout).

# INTERFACE & VISUALIZATION STYLE
The `asciiGraph` string must look incredibly clean, using block elements (e.g., '▓' or '█') to construct clear progress tracks next to each letter-coded parameter label, drawing a definitive marking point for where the user lands. Ensure that the text response uses off-white parameters matching a light/neutral natural palette if parsing to HTML later.

# ERROR HANDLING
- Validate that exactly 30 valid responses are parsed inside the dataset.
- Implement data fallbacks so that any unexpected response structure treats the calculation score as neutral (0) instead of throwing undefined crash stack traces.
